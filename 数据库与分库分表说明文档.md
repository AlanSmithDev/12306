# 12306 数据库与分库分表说明文档

> 本文档详细记录12306铁路购票系统的数据库设计、分库分表规则、加密配置等内容。

---

## 一、数据库整体规划

### 1.1 数据库架构

该项目采用分库分表架构，支持聚合版和微服务版两种部署模式。

| 模式 | 数据库数量 | 特点 |
|------|------------|------|
| 聚合版 | 1个 | 单库多表，适合快速启动 |
| 微服务版 | 4个 | 按业务域分库，适合学习微服务 |

### 1.2 聚合版数据库

| 数据库 | 用途 |
|--------|------|
| 12306 | 聚合模式下所有业务表 |

### 1.3 微服务版数据库

| 数据库 | 用途 | 主要表 |
|--------|------|--------|
| 12306_user | 用户域 | t_user、t_passenger、t_user_phone、t_user_mail |
| 12306_order | 订单域 | t_order、t_order_item、t_order_item_passenger |
| 12306_pay | 支付域 | t_pay |
| 12306_ticket | 票务域 | t_train、t_station、t_seat、t_ticket |

## 三、分库分表规则

### 3.1 分片策略

| 表类型 | 分片键 | 分片算法 | 分片数 |
|--------|--------|----------|--------|
| 用户域表 | user_id | 取模 | 32 |
| 订单域表 | user_id | 取模 | 32 |
| 支付表 | user_id | 取模 | 32 |
| 票务表 | train_id | 取模 | 16 |

### 3.2 分片算法实现

```java
/**
 * 用户域分片算法
 * 根据userId取模确定分片
 */
public class UserModShardingAlgorithm implements ComplexKeysShardingAlgorithm {
    
    @Override
    public Collection<String> doSharding(
            Collection<String> availableTargetNames,
            ComplexKeysShardingValue<Object> shardingValue) {
        
        Long userId = (Long) shardingValue.getColumnNameAndRangeValuesMap()
                .get("user_id").iterator().next();
        
        // 计算分片号：userId % 分片数
        int shardingIndex = (int) (userId % 32);
        String suffix = shardingIndex < 10 ? "0" + shardingIndex : String.valueOf(shardingIndex);
        
        // 查找目标表
        for (String targetName : availableTargetNames) {
            if (targetName.endsWith("_" + suffix)) {
                return Collections.singletonList(targetName);
            }
        }
        
        throw new UnsupportedOperationException("未找到目标分片: " + shardingIndex);
    }
}
```

### 3.3 分片表命名

#### 聚合版分片命名

```sql
-- 用户域（16分片）
t_user_0 ~ t_user_15
t_passenger_0 ~ t_passenger_15
t_user_phone_0 ~ t_user_phone_15
t_user_mail_0 ~ t_user_mail_15

-- 订单域（16分片）
t_order_0 ~ t_order_15
t_order_item_0 ~ t_order_item_15
t_order_item_passenger_0 ~ t_order_item_passenger_15

-- 支付域（16分片）
t_pay_0 ~ t_pay_15
```

#### 微服务版分片命名

```sql
-- 用户服务（32分片）
12306_user_0.t_user_0 ~ t_user_31
12306_user_1.t_passenger_0 ~ t_passenger_31

-- 订单服务（32分片）
12306_order_0.t_order_0 ~ t_order_31
12306_order_1.t_order_item_0 ~ t_order_item_31

-- 支付服务（32分片）
12306_pay_0.t_pay_0 ~ t_pay_31
```

### 3.4 ShardingSphere配置示例

**聚合版配置**（shardingsphere-config-dev.yaml）：

```yaml
dataSources:
```

## 四、数据加密配置

### 4.1 加密字段列表

| 表名 | 加密字段 | 加密算法 |
|------|----------|----------|
| t_user | id_card、phone、mail、address | AES |
| t_passenger | id_card、phone | AES |
| t_order_item | passenger_id_card | AES |
| t_order_item_passenger | id_card | AES |

### 4.2 加密配置

```yaml
rules:
  - !SHARDING
    # ... 分片配置 ...
  
  - !ENCRYPT
    encryptors:
      aes_encryptor:
        type: AES
        props:
          aes.key.value: your-aes-secret-key  # 替换为实际密钥
    tables:
      t_user:
        columns:
          id_card:
            plainColumn: id_card_plain
            cipherColumn: id_card
            encryptorName: aes_encryptor
          phone:
            plainColumn: phone_plain
            cipherColumn: phone
            encryptorName: aes_encryptor
          mail:
            plainColumn: mail_plain
            cipherColumn: mail
            encryptorName: aes_encryptor
          address:
            plainColumn: address_plain
            cipherColumn: address
            encryptorName: aes_encryptor
```

### 4.3 加密使用注意事项

1. **明文字段**：需要添加对应的明文字段（如 `id_card_plain`）用于展示
2. **查询处理**：密文字段无法直接用于WHERE条件，需要使用密文或通过应用层处理
3. **密钥管理**：生产环境建议使用配置中心或密钥管理服务存储密钥

## 六、Redis缓存设计

### 6.1 缓存Key规范

| 业务场景 | Key格式 | TTL | 说明 |
|----------|---------|-----|------|
| 登录态 | `index12306:login:{token}` | 30min | 用户登录信息 |
| 用户信息 | `index12306:user:{userId}` | 1h | 用户详情缓存 |
| 用户名集合 | `index12306:user:recycle:{username}` | 永久 | 可复用用户名 |
| 车站缓存 | `ticket:station:all` | 24h | 所有车站 |
| 区域站点 | `ticket:region:{regionCode}` | 24h | 区域站点映射 |
| 列车信息 | `ticket:train:{trainId}` | 12h | 列车详情 |
| 价格缓存 | `ticket:price:{trainId}:{seatType}` | 24h | 座位价格 |
| 余票令牌 | `ticket:token:{trainId}:{from}:{to}:{seatType}` | - | 令牌桶计数 |
| 布隆过滤器 | `bloom:user:register` | - | 注册防穿透 |

### 6.2 缓存更新策略

| 缓存类型 | 更新策略 | 说明 |
|----------|----------|------|
| 登录态 | 删除 | 登出时删除 |
| 用户信息 | 更新 | 用户修改时更新 |
| 车票缓存 | TTL过期 | 5分钟自动过期 |
| 令牌桶 | 原子扣减 | Lua脚本保证一致性 |
| 布隆过滤器 | 只增不减 | 用户注销时重建 |

## 七、索引设计

### 7.1 索引类型

| 索引类型 | 使用场景 |
|----------|----------|
| 主键索引 | 唯一且非空 |
| 唯一索引 | username、phone、mail等唯一字段 |
| 普通索引 | 外键关联、状态查询、日期查询 |
| 联合索引 | 复合查询条件 |

### 7.2 重要索引

```sql
-- 用户表
PRIMARY KEY (`id`)                    -- 主键
UNIQUE KEY `uk_username` (`username`) -- 用户名唯一
KEY `idx_phone` (`phone`)             -- 手机号查询
KEY `idx_mail` (`mail`)               -- 邮箱查询

-- 订单表
PRIMARY KEY (`id`)                    -- 主键
UNIQUE KEY `uk_order_sn` (`order_sn`) -- 订单号唯一
KEY `idx_user_id` (`user_id`)         -- 用户订单查询
KEY `idx_status` (`status`)           -- 状态查询
KEY `idx_create_time` (`create_time`) -- 时间排序

-- 支付表
PRIMARY KEY (`id`)
UNIQUE KEY `uk_pay_sn` (`pay_sn`)     -- 支付单号唯一
UNIQUE KEY `uk_order_sn` (`order_sn`) -- 订单号唯一（防重复支付）
```
